## 什么时候往里写

出现下面任一情况：

- 一个决策**有争议**，且事后很难从代码看出来（例如「为什么 gateway 不做业务，只做 BFF」）；
- 换了技术选型，需要留下「为什么换、放弃了什么」；
- 某处结构看起来「奇怪但其实有原因」，新同学大概率会想改掉它。

## ADR 怎么写

一份决策一个文件：`NNNN-<短标题>.md`，只回答四件事：

```text
# <标题>

状态：提议 / 已采纳 / 被 NNNN 取代
背景：当时面对什么约束
决策：选了什么，放弃了哪些选项，各自代价
后果：因此要长期忍受什么（诚实地写代价）
```

> 已采纳的决策**不要原地改**。要改就新写一份并标「取代 NNNN」——
> 历史决策被改写之后，后来的人无法理解当时为什么那么做。
