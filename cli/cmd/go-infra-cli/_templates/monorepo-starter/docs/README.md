## 边界

- 这里放**跨 Project** 的内容。单个 Project 的说明写在它自己的 `README.md`。
- 目录职责的**权威说明在根 `README.md`**（含「7 个问题」）。这里不重复抄一份，只做链接与展开。
- 规范类内容优先写成**可执行的约束**（`.cursor/rules/*.mdc`、`tools/lint/check-structure.py`、CI 检查），
  文档只解释「为什么」。能靠工具拦住的规则，不要只写在文档里。
- 与根 `README.md` 重复的内容不要在这里再抄一遍，用链接指向它。

## 该写什么

- **架构决策（ADR）**：一个决策一份文件，写完不再改（要改就写新的一份并标注取代关系）。
  记「当时为什么这么选、放弃了什么」，而不是复述最终结构 —— 最终结构看代码。
- **排查手册**：按**症状**组织（症状 → 原因 → 处置），不要按组件组织 —— 出事时没人先想到「是哪个组件」。
- **约定**：能写成脚本或规则文件的一律写成脚本 / 规则文件，这里只留「为什么」。

> `architecture/` 与 `conventions/` 目前为空：架构总览在根 `README.md`，
> 约定在 `.cursor/rules/`。有超出这两处的决策再往这里放。
